<h3 id="a2-insufficient-token" style="color:#00695c;font-size:1.05em;font-weight:600;margin-top:0.85em">2.1.1 Why `Insufficient_Information_Based_On_Given_PDF` appears with other text</h3>

**Prompt contract** (`tests/retail_multi_profiles/lib/answer_pipeline.py`): if excerpts are not enough, the answer model should reply **exactly** that string — **no other words**.

**What the harness actually stores:** the **raw** answer string from the LLM (`candidate_answer` in `results.json`). There is **no** post-processor that strips prose or enforces exclusivity before save or judge.

**How it is scored:**

| Stratum | Scoring | Insufficient token |
|---------|---------|-------------------|
| **negative** questions | `score_negative` — **exact** match to `insufficient_literal` only | Must be the **whole** answer |
| **easy / hard** (answerable) | `score_judged` — Gemini judge sees the **full** candidate | Prose **+** suffix is one string; judge may **pass** on the prose and ignore a contradictory suffix (e.g. §2.1 row **4** `GNE27JYMFS-H10`) |

**Lane B v2 frequency (mixed = prose + token):** vector **6/60**, hybrid **5/60** (includes **H10 pass**), rerank **4/60**. These are **model non-compliance** with the prompt, not a second “conclusion channel” in code.

**Table source (recheck):** every cell is **`lane=B`** and **`difficulty` ∈ {easy, hard}** from the listed `run_id` paths. For vector, never index by `question_id` alone — the same id appears on lanes **A–D** in `abcd-raw-full-openai-v1`.
